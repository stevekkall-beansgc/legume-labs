## What a bounded review story can show

1. Define the artifact and the failure it should catch.
2. Inspect a genuine before/after change and separate a code finding from a claim about users or outcomes.
3. Check whether the tests exercise that failure and whether the normal workflow actually runs them.
4. Keep the decision with a person; preserve negative or inconclusive results rather than calling every run successful.

These are the interpretation of the linked artifacts, not a claim that this sequence was executed by the private systems below. Their public role description is historical context only.
